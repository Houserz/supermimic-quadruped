# 行走规划器与技能

[English](PLANNER.md) · **简体中文**

一个 SONIC 风格的运动学规划器：摇杆给出速度，规划器写出接下来 1 秒的参考动作，动作跟踪策略去执行。跟踪器就是跟踪动捕动作库的那一个，
行走不需要重新训练。

```
按键 ─► 摇杆目标 ─► RateLimiter ─► 规划器（每 5 步）─► 参考队列 ─► 接下来 10 帧 ─► 跟踪器 ─► 机器人
                    ≥ 0.2 秒渐变   0.5 秒上下文 + 摇杆     交叉过渡 5 帧    （目标特征）
                                   + 步态时钟 ─► 1 秒规划
```

## 组成

| 文件 | 内容 |
|---|---|
| `src/supermimic/planner/features.py` | 每帧 20 个数：关节角 − 默认站姿、机身高度、机身坐标系下的重力方向、朝向坐标系下的速度、偏航角速度；以及把它们积分回位姿 |
| `src/supermimic/planner/model.py` | 残差 MLP，1024 × 4 个块（1000 万参数）：25 帧上下文 + 条件 → 50 帧，以最后一帧上下文为基准预测残差 |
| `src/supermimic/planner/goal.py` | 规划帧 → 跟踪器的目标特征，直接调用动作库自己的 `goal_features` |
| `src/supermimic/planner/rover.py` | Rover 的默认站姿和足端、随机摇杆、步态时钟、速度映射、摇杆渐变 |
| `src/supermimic/planner/rover_skills.py` | `SkillDriver`：行走来自规划器，技能来自动作库片段，每次切换都经过站立；站立保持 |
| `src/supermimic/planner/session.py`、`keys.py`、`hud.py` | 一台由摇杆驱动的机器狗、键盘、屏幕上的按键显示 |
| `scripts/planner/teleop.py` | 在 MuJoCo 窗口里实时键盘操控（`--selftest` 不开窗口，按预设按键自检） |
| `scripts/planner/render_teleop.py` | 演示视频：预设按键、规划器画在机器狗旁边、屏幕上显示按键 |
| `scripts/planner/closed_loop.py` | 多台机器狗在随机摇杆下运行：摔倒、速度增益、跟踪误差、扭矩 |
| `scripts/planner/fit_velocity_map.py`、`train_planner.py` | 用自己的行走数据训练 |

## 设计

- **局部特征，只看自己的输出。** 每帧里没有全局位置和朝向，所以规划从机器人当前所在的地方开始。规划器的上下文是它自己已经执行的规划，
  从不读取机器人状态：跟踪器拿到的参考始终和训练数据同一个样子，机器人踉跄一下也不会反馈进规划里。训练时让规划器在自己（截断梯度的）
  输出上最多连续重新规划 20 次（2 秒），让它学会不偏离数据。
- **步态时钟。** 产生数据的行走策略有一个 0.6 秒的自由运行步态时钟，指令小于 0.1 时关闭。步态启动时先抬哪一对对角腿取决于这个时钟，
  只看指令的规划器只能猜，把各种猜测平均成又短又打滑的步子（慢速原地转身打滑 18–21 cm/s，数据里是 3 cm/s）。所以规划器把时钟（sin、cos）
  作为额外两个输入，部署时自己运行一份时钟。
- **摇杆值就是速度。** 行走策略在 vx / vy / 偏航角速度上只能达到指令的约 0.88 / 0.71 / 0.92。`fit_velocity_map.py` 拟合行走策略的稳态映射 G
  （指令 → 速度，多项式）及其反函数；规划器用 G(指令) 作为标签训练，所以摇杆值就是机器人实际走的速度。时钟的开关按 G⁻¹(摇杆值)
  判断，也就是走出这个速度所需的指令。
- **摇杆渐变。** 摇杆目标的每次变化都变成至少 0.2 秒的线性渐变，各轴同时渐变，和录制数据时一样。更快的变化在数据之外：慢速转身在 0.1 秒内
  松开时，规划器会一直原地摇摆。
- **站立保持。** 摇杆归零、已执行的参考站稳 0.5 秒且四只脚都着地后，不再调用规划器，参考停在这一帧，直到摇杆再动。如果规划在 2 秒内没站稳，
  就过渡到一帧站姿（很少见：慢速转身后约 2.4 Hz 的偏航摇摆）。
- **技能。** 按技能键后，摇杆先渐变到零，等规划站稳，把技能对应的动作库片段放到当前的脚上（二维刚体配准），保持脚着地过渡进去
  （机身走最小加加速度轨迹，腿用 IK），播放，再过渡回一帧站姿，把参考交还给规划器。

## 结果（`rover_v2_l1` + `rover_r2`）

`closed_loop.py --val-every 1 --clips 125`：125 台机器狗各 60 秒，从行走数据的验证片段起步，随机摇杆覆盖摇杆的全部范围
（vx −0.8..1.5 m/s、vy ±0.5 m/s、偏航角速度 ±0.9 rad/s；每个值保持 1–5 秒，渐变 0.2–1 秒）：

| | 无随机化 | 域随机化 |
|---|---|---|
| 摔倒 | 0 | 0 |
| 机器人 / 摇杆，所有帧 vx / vy / 偏航角速度 | 0.97 / 0.99 / 0.98 | 0.97 / 1.00 / 0.98 |
| 机器人 / 摇杆，纯横移 / 纯转向 | 0.99 / 0.98 | 1.00 / 0.97 |
| 稳态 \|机器人 − 摇杆\|，vx / vy（m/s）/ 偏航角速度（rad/s） | 0.018 / 0.010 / 0.015 | 0.020 / 0.014 / 0.022 |
| 相对规划的跟踪误差：关节 / 高度 / 倾角 | 0.052 rad / 4.4 mm / 1.65° | 0.053 rad / 4.5 mm / 1.73° |
| 有关节达到扭矩上限的步数 | 0 % | 0 % |

规划本身是摇杆的 1.00 倍，剩下 2–3% 的差距在跟踪器。没有行走数据时（只有发布的文件），`closed_loop.py` 让每台机器狗从 `stand_seed.npz`
起步：32 台 × 30 秒，0 次摔倒，0.97 / 1.00 / 0.98。已知的不足：0.25 rad/s 的转向会少转约 9%；相邻两次规划衔接处有轻微的 10 Hz
关节加速度波动；以及上面说的偏航摇摆。

## 用自己的行走数据训练

行走数据不公开（本地训练的 RL 行走策略的 12.5 小时录制）。要给别的机器人或别的策略训练规划器，需要自己录：

1. 用 `planner.rover.RoverCommands` 驱动行走策略（每台机器人：一个指令保持 1–5 秒，0.2–1 秒渐变到下一个；15% 为零，15% 纯转向，
   25% 只有一个平移方向；渐变速率上限 `ACC_CMD_V2`），以 50 Hz 录制。我们的：300 台 × 150 秒，指令范围 vx −1..1.7、vy ±0.75、偏航角速度 ±1。
2. 每段录制存成一个 `<名字>_e<编号>_s<k>.npz`，采用 mjlab 动作格式（`joint_pos`、`joint_vel`、`body_pos_w`、`body_quat_w`（wxyz）、
   `body_lin_vel_w`、`body_ang_vel_w`、`joint_names`、`body_names`、`fps`；即 [PORTING.zh-CN.md](PORTING.zh-CN.md) 里的片段格式），
   另加 `cmd`（T, 3），每帧给的指令；带时钟的规划器还需要 `clock_step`（T,），每帧对应的策略步数。`e % 10 == 9` 的录制作为验证集。
3. 拟合速度映射并训练，然后评测、操控：

```bash
uv run python scripts/planner/fit_velocity_map.py --npz-dir data/planner/rover_v2/npz
uv run python scripts/planner/train_planner.py --npz-dir data/planner/rover_v2/npz --run my_planner   # 约 26 分钟，RTX 5070
uv run python scripts/planner/closed_loop.py --planner-run my_planner --clips 125 --val-every 1
MUJOCO_GL=glfw uv run python scripts/planner/teleop.py --planner-run my_planner
```

检查点旁边没有 `stand_seed.npz` 时，操控从行走数据里 `rover_e009_s0` 的第 60 帧起步（可用 `--clip` 换），技能用的站姿从验证片段里取。
